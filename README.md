# Qflow Signal — MVP prototype
Local: set ADMIN_PASSWORD and WEBHOOK_SECRET, run `python app.py`, open http://localhost:8000, sign in and load mock signals from Settings. SQLite is used locally. Render uses PostgreSQL through DATABASE_URL. Optional OPENAI_API_KEY enables structured LLM analysis; otherwise explicitly labeled heuristic mode. No outbound Reddit posting. Mock links point to subreddit, not real posts.

Webhook: POST /api/webhooks/prowlo with Authorization: Bearer <WEBHOOK_SECRET> and JSON {"id":"unique-id","subreddit":"askcarsales","title":"...","body":"...","author":"...","url":"https://www.reddit.com/r/askcarsales/comments/...","timestamp":"ISO8601","kind":"post","parent":"","keyword":"BDC"}. This is a proposed normalized contract, not verified against Prowlo. Configure a provider adapter once actual payload and authentication are known. Duplicate IDs are cached. In-app alerts are persisted. Author activity intentionally unknown until authorized data source exists. Email/Slack/browser push, live refresh, granular filtering, production authentication/rate limiting, asynchronous webhook jobs and real provider testing remain follow-up work. Settings for keywords/subreddits do not change provider subscriptions. Approval is manual copy/open only, not proof of posting.

Render: push files to a private Git repository connected to Render, create Blueprint from render.yaml, review plan and configure secrets. Verify free plans and retention before using real data. Public URL is login-gated; webhook is bearer-protected. Use a strong unique admin password and webhook secret. No production deployment performed. Do not commit secrets or database files.
